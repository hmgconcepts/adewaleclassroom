Platform health

Platform health🔐 Owner / admin only

One console that answers "is the studio still working?": the keep-alive heartbeat that stops Supabase pausing a free project after seven idle days (and exactly where the last ping came from), the HMG Fleet Console linkage, a Schema Doctor that lists every SQL pack and whether it is installed, database size against the 500 MB limit, file-storage health, the last Drive backup, the licence position, the idle-lock setting, and the sign-in audit showing exactly who logged in. Anything amber or red here becomes an outage if it is ignored.

Who it is for. Owner and admin. This is configuration and governance, not day-to-day teaching.

Why it matters. Free-tier Supabase pauses idle projects and caps the database at 500 MB. Both are survivable — but only if somebody is watching. This page is that somebody.

How to use this page
  1. Check the heartbeat card — the ping should be no more than a few days old and show a source (this console, the fleet console, or automation).
  2. Register the project in the HMG Fleet Console so it is pinged automatically, then confirm the fleet card turns green.
  3. Run the Schema Doctor and install any pack it lists as missing.
  4. Watch database usage; archive and purge from Storage Manager when it climbs.
  5. Review the sign-in audit for anybody who logged in that you do not recognise.
What each role sees here
  • Owner: Full access.
  • Admin: Full access.
  • Tutor: No access.
  • Parent / Learner: No access.

💓 Keep-alive (anti-pause)

Supabase pauses free projects after ~7 idle days. Every ping below resets that clock — from this console, from the HMG Fleet Console, or from your own automation. The source column tells you exactly who saved it last.

⬇ keep-alive.sql

The ping writes through tc_keep_alive('manual-health-page') — the same endpoint every layer below uses — so the console and the database always agree on one heartbeat.

🛰️ HMG Fleet Console linkage

The Fleet Console monitors every client Supabase project and one-click prevents pausing. This project is fleet-ready when the compatibility pack (sc_keep_alive RPC, sc_keepalive table, sc_license_status RPC) is installed.

Checking…
  1. Run database/v11-enterprise-pack.sql in the Supabase SQL Editor (already inside complete-schema.sql for new installs).
  2. Open the Fleet Console → Projects → Add project, and paste this project's URL + anon key.
  3. The console pings rpc/sc_keep_alive with src: "hmg-fleet-console"; the source appears in the heartbeat tile above.

🫀 Keep-alive layers — who protected the project, and when

Supabase pauses a free project after ~7 days with no database activity. Ten-plus layers guard against that; until now only the last ping was visible. This panel reports every layer — including ones that have never run — straight from the per-source ledger (tc_keepalive_sources), so you can see each layer carrying out its function, and exactly how to start any that is stale.

🩺 Schema Doctor — is every SQL pack installed?

The database itself reports every pack in database/ and whether its signature object is present. A missing pack means the files expect objects the database does not have yet — run the named file in the Supabase SQL Editor, then notify pgrst, 'reload schema';
