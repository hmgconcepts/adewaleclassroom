1. Direct from tablet: the 6-step quick start

  1. Deploy the relay once: upload the included relay/no-obs-social-relay/ folder to a free/low-cost host with HTTPS (Render, fly.io, Vercel-docker, a $4 VPS all work). Note its address — that is your gateway URL (e.g. https://class-relay.yourname.onrender.com).
  2. Get a stream key: on the platform(s) you want (YouTube, Facebook, TikTok, Instagram…), start creating a live stream and copy the stream key it shows you (exact click-paths in section 4 below).
  3. Open Teacher Studio on your tablet → ⚙ Settings → 📡 Tablet Live.
  4. Paste your gateway URL and each platform key into a destination row (the server URL fills itself in — never type it by hand).
  5. Do a 60-second dry run: press ▶ Start, check the preview appears on the platform, then ■ Stop. Delete the dry-run recording.
  6. Go live for the class: ▶ Start social live. Classroom Deck sends the lesson canvas + mic to the relay; the relay publishes to your platforms.
Why a relay is needed: the modern web browser can send WebRTC, but social platforms still commonly require RTMP/RTMPS ingest. The relay converts WebRTC to RTMP without needing OBS on the tablet.
Already set up on another device? Sign in with your ADEWALE CLASSROOM account — the gateway, secret and every key are restored automatically, and there is a ☁️ Restore from cloud button in the Tablet Live panel to pull them on demand.

2. Every field explained — Settings → 📡 Tablet Live

Each row matches a field in the Tablet Live panel exactly. For every field: what it is, a copy-paste example, and the mistake new users make — with the ✅ right way and the ❌ wrong way side by side.

FieldWhat it is · exampleNew-user mistake (✅ / ❌)
Relay gateway URL The HTTPS address of YOUR deployed relay (step 1 above). Example: https://class-relay.yourname.onrender.com — the WHIP pattern is https://YOUR-RELAY-DOMAIN/rtc/v1/whip/?app=live&stream=classdeck. Must start with https://: the browser blocks an http:// gateway on an HTTPS page, and the preflight catches it before you stream. ❌ pasting the whole WHIP path, or http://, or the host's dashboard URL.
✅ just the domain root: https://class-relay.yourname.onrender.com — Classroom Deck adds the rest.
Gateway secret The shared password you set on the relay (its SECRET environment variable) — only people who know it can publish through your relay. Example: a-long-passphrase-only-you-know. Leave empty if your relay does not require one. ❌ typing the platform stream key here (they are different things: secret = relay password, key = platform password).
✅ the same passphrase you put in the relay's SECRET env var — or leave blank if you never set one.
Stream name A name for THIS device's feed — letters, digits and dashes only. Pre-filled as classdeck-<room code>. Example: classdeck-math10a. Two teachers streaming at the same time must use different stream names. ❌ spaces or emoji (rejected), or the same name on two tablets at once (the feeds fight).
✅ classdeck- + your room code, one per concurrent teacher.
Format Landscape 16:9 for YouTube / Facebook / Twitch, or Vertical 9:16 for TikTok / Instagram (the class canvas is framed full-height with your camera picture-in-picture). ❌ landscape to TikTok/Instagram → ugly black bars left+right (the preflight warns you).
✅ match the destination: 16:9 YouTube/Facebook, 9:16 TikTok/Instagram.
Frame rate 10 fps for weak/mobile upload · 15 fps recommended · 24 fps smooth · 30 fps only on strong upload. The panel shows an honest bitrate hint for each choice. ❌ 30 fps "because it's better" on mobile data → the encoder can't keep up and the stream stutters.
✅ 15 fps. If your viewers report lag, drop to 10 before touching anything else.
Destination — platform Pick YouTube, Facebook, TikTok, Instagram, Twitch, Kick or Custom RTMP. The correct RTMP/RTMPS server is filled in automatically — you never type a server URL by hand (hand-typed servers are the #1 cause of failed streams). ❌ choosing "Custom RTMP" because you don't see your server yet, then typing a URL with a typo.
✅ pick the platform by name — the server fills itself. Custom RTMP is only for platforms not in the list.
Destination — key The stream key from the platform dashboard (where to find it: section 4). Example (YouTube): ab3d-1234-5678-9def. Keys are masked and never logged; pasting a full rtmp://… URL by mistake is understood, not rejected. YouTube keys go stale after a few uses — copy a fresh one if the stream is refused. ❌ reusing last week's key (expired on YouTube/Instagram), or pasting the stream URL into the key box AND the server box.
✅ copy a fresh key for each live session; paste it in the key box only.
Destination — server Auto-filled from the preset (YouTube rtmp://a.rtmp.youtube.com/live2, Facebook rtmps://live-api-s.facebook.com:443/rtmp/…). Only Custom RTMP asks you to type one — paste it exactly as your provider shows it. The full publish URL sent to the relay is server/key. ❌ "fixing" the auto-filled URL because it looks unusual.
✅ leave the auto-fill alone — it is the platform's current ingest address.
⚡ Smart paste box Paste anything — a bare key, a full rtmp(s)://server/app/KEY URL, or the whole block copied from the platform page (even when it mentions the platform by name) — and Classroom Deck works out the platform, server and key and adds the row for you. ❌ typing a key by hand, character by character, from a paper note.
✅ copy from the platform page → paste into the smart box → row appears complete.

Unchecked = only the gateway, stream name and format are kept, and the keys are re-entered next time. ❌ unchecking it on a shared/public tablet is right, forgetting to RE-check on your own tablet next time.

3. Platform cheat-sheet — exactly where the key lives

▶ YouTube

Path: studio.youtube.com → Go Live (or Create → Go live) → choose Streaming software → the page shows Stream key (paste into your software) → copy.
Server: auto-filled (rtmp://a.rtmp.youtube.com/live2).
Key looks like: ab3d-1234-5678-9def.
Format: 16:9 · 15 fps. Notes: the stream appears as "waiting for signal" — your tablet IS the signal. Eligibility: 24h wait on brand-new channels, live streaming must be enabled in settings (can take 24 h to activate).

f Facebook

Path: facebook.com/live/producer → choose Streaming software → copy the stream key.
Server: auto-filled (rtmps://live-api-s.facebook.com:443/rtmp/).
Key looks like: a long 0-RA… string.
Format: 16:9 · 15 fps. Notes: after the preview appears you may still need to press Go Live inside Facebook. Pages with repeated policy strikes lose live access.

🎵 TikTok

Path: livecenter.tiktok.com (or the app → Live Center → LIVE Studio access) → RTMP → copy the URL and key shown.
Key looks like: shown once, with the RTMP URL beside it.
Format: 9:16 vertical (landscape gets bars) · 15 fps. Notes: RTMP streaming needs a LIVE-eligible account (usually 1,000+ followers and 18+; check Live Center availability in your region). Not eligible? Stream to YouTube and share the link to TikTok instead.

📸 Instagram

Path: a professional/creator account → Live producer on desktop (instagram.com → Create → Live producer) → copy the stream key.
Key looks like: temporary, usually shown per-live-session.
Format: 9:16 vertical · 15 fps. Notes: keys are short-lived — generate a fresh one for each class; a stale key is the #1 Instagram failure. Personal (non-professional) accounts do not get RTMP keys.

🎮 Twitch / Kick

Path (Twitch): dashboard.twitch.tv → Settings → Stream → Primary Stream key → copy.
Server: auto-filled (rtmp://live.twitch.tv/app).
Format: 16:9 · 15 fps.
Notes: Twitch keys are long-lived; Kick follows the same pattern from its Creator Dashboard → Streaming keys.

🔧 Custom RTMP

For any platform not listed (LinkedIn events, a church system, your own media server): pick Custom RTMP and paste the publish URL exactly as the provider prints it — including the app path, e.g. rtmps://ingest.example.com/live. This is the only place you ever type a server by hand.

Protect stream keys: do not commit keys to GitHub, do not paste them into chats. Enter them only on your own tablet and relay over HTTPS. Obtain consent before publicly streaming minors — parents' permission first, always.

5. Full tablet screen vs Classroom Deck screen

On many Android tablets, browser security does not expose full-system screen capture to websites. Classroom Deck therefore provides two routes:

  • Classroom Deck workspace capture: always available because the app captures its own teaching canvas.
  • Full tablet screen attempt: available only if the tablet/browser supports getDisplayMedia.
If full Android screen capture is not available, your students/social audience still see the whole Classroom Deck teaching workspace — whiteboard, PDFs, browser cast, notes, toolkit, camera, captions and overlays.
