How multi-line maths & images work in CSV

  • Fractions, roots, indices, matrices: write real LaTeX in the cell — \frac{a}{b}, \sqrt[3]{27}, x^{n+1}, \begin{pmatrix} 2 & -1 \\ 3 & 4 \end{pmatrix}. Since V39 the candidate screen draws these as genuine typeset maths (stacked fraction with a bar, full-height matrix brackets), not as raw backslash text. No CDN, no MathJax — it renders offline.
  • Line breaks inside a cell: use the two characters \n. They become real line breaks on the candidate screen. Safe next to maths: \neq still renders as ≠.
  • Pinned passages: repeat the full passage in Col14 {"passage":"…"} on every row of a comprehension set and tag them set:P1. The platform then shows that passage once, pinned above the question, for every question in the set — with a live “3 of 5 answered” counter — instead of it disappearing between questions.
  • Read-aloud: candidates can have any question and its options spoken by their own device (free, offline, no API key). Maths is spoken in words — \frac{3x+6}{9} is read as “the fraction 3x plus 6, over 9” — which only works if you use the commands above rather than flattening to 3x+6/9.
  • Randomisation: question order and option order can be randomised per candidate in the CBT setup. Marking compares answer text, never the A–D letter, so shuffling cannot change a score — but it does mean explanations must name the answer in words, not as “Option B”.
  • Images / diagrams: put a public https:// or Google Drive link in media_url (or Col14 JSON {"image":"https://..."}). Always add a text fallback in the stem (“The diagram shows…”). Nothing is uploaded into free Supabase storage.
